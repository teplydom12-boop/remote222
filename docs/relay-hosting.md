# Сервер очереди и вход в аккаунт

Windows и облачный контроллер подключаются исходящими HTTPS-запросами к одному
серверу. Он хранит очередь, результаты и сведения о сеансах в SQLite. На Windows
не нужны публичный IP, входящий порт или Cloudflare Tunnel; видимое приложение
Remote222 должно оставаться запущенным.

В версии 0.4 основной способ входа — логин и пароль на Windows и подтверждение
контроллера в браузере. Для существующего VPS используйте
[обновление аккаунта](vps-account.md), для нового Ubuntu VPS —
[первоначальную установку](vps-ubuntu.md). Дальше описан другой вариант:
управляемый Docker-хостинг с постоянным диском и HTTPS.

## Размещение Docker-сервиса

Подойдёт хостинг с приватным интерактивным терминалом контейнера, постоянным
диском и управляемым HTTPS, например Render Web Service. Параметры задаются
в [панели хостинга](https://dashboard.render.com/).

1. Создайте сервис из `https://github.com/teplydom12-boop/remote222`, ветка
   `main`, Dockerfile в корне. Выберите одну реплику и проверьте стоимость
   сервиса и постоянного диска перед активацией.
2. Подключите постоянный диск по пути `/var/data/remote222`. Для личной установки
   можно начать с 1 ГБ. На нём должны сохраняться очередь, история и
   `auth.sqlite3`; временная файловая система для них не подходит.
3. Получите канонический HTTPS-адрес сервиса. В настройках команды запуска
   укажите его в `--public-url`:

   ```text
   python -m remote222.broker --host 0.0.0.0 --port 8770 --state-dir /var/data/remote222 --public-url https://<адрес-сервиса>
   ```

   Внутренний HTTP-порт — `8770`, путь проверки состояния — `/healthz`.
   HTTPS завершает штатный прокси хостинга. Значение `PORT` само по себе не
   заменяет порт в команде запуска. Для страницы подтверждения нужен правильный
   `--public-url`; в нём нет пути, пароля или параметров запроса.
4. В приватном интерактивном терминале работающего контейнера создайте аккаунт:

   ```sh
   python -m remote222.broker --state-dir /var/data/remote222 --set-account
   ```

   Введите логин и пароль по приглашению, затем повторите пароль. Пароль
   не отображается и не передаётся через аргументы команды. Сервер сохраняет
   его хеш. После создания аккаунта прежние статические ключи очереди отключаются;
   распространять файлы ключей или задавать секреты контроллера и Windows не нужно.
   Повторный `--set-account` заменяет аккаунт и отзывает прежние сеансы.
   После создания аккаунта добавьте `--account-only` к команде запуска и
   перезапустите сервис. Тогда потеря базы аккаунта остановит запуск сервера,
   а прежняя авторизация по ключам не включится автоматически.
5. Прокси должен пропускать запросы размером не менее 12 МиБ: результат может
   занимать до 8 МиБ плюс JSON-конверт. Не запускайте несколько реплик broker
   поверх одного SQLite-файла.
6. Проверьте `https://<адрес-сервиса>/healthz` из Windows и облачной среды.
   Успешный ответ подтверждает доступность сервиса; сведения от ПК проверяются
   отдельно после входа Windows. Адрес должен быть явно разрешён обеим сторонам.
   Хостинг или сеть всё ещё могут вернуть HTTP 403 или другую ошибку.

Контейнеру требуется запись только в каталог данных. Docker socket, файлы хоста
и привилегированный режим не нужны. Внутренний HTTP-порт не публикуется наружу
без HTTPS-прокси. Клиенты проверяют сертификат и не отправляют учётные данные
при перенаправлении на другой адрес.

## Подключение Windows и контроллера

В Remote222.exe v0.4 выберите **Через сервер очереди**, заполните
**HTTPS-адрес вашего сервера очереди**, **Логин** и **Пароль**, затем нажмите
**Включить управление**. Приложение сохраняет сеанс, но не пароль. При повторном
запуске пароль не нужен, пока сохранённый вход действует.

В облачной среде разрешите точное имя сервера обычным способом через сетевые
настройки. Секрет `REMOTE222_TOKEN` для аккаунта не требуется. Пример для VPS
`95.163.231.24` после [обновления HTTPS и аккаунта](vps-account.md):

```sh
python3 -m remote222.client --url https://95-163-231-24.sslip.io --session-file /workspace/.remote222-controller/session.json connect
```

Для другого хостинга замените URL. Контроллер напечатает ссылку `/connect` и код.
Откройте ссылку в своём браузере, введите код, логин и пароль и подтвердите
подключение. Код действует 10 минут. После подтверждения профиль сохранится
в указанном файле за пределами репозитория; его содержимое не нужно копировать
в настройки среды или чат.

```sh
python3 -m remote222.client --session-file /workspace/.remote222-controller/session.json session
python3 -m remote222.client --session-file /workspace/.remote222-controller/session.json info
```

`session` проверяет вход на сервер. `info` получает свежий ответ Windows через
очередь: перед выполнением команд убедитесь, что отвечает нужный компьютер.
Указывайте тот же `--session-file` для всех действий: сохранённый адрес имеет
приоритет над устаревшими переменными окружения прежнего режима.

Сеанс действует 30 дней. Новое подтверждение нужно после истечения, отзыва или
потери профиля, например при замене облачной рабочей среды. **Отключить** и
закрытие окна Windows сохраняют вход, прекращая новые задания.
**Выйти из аккаунта** удаляет вход и запрашивает его отзыв на сервере; если связь
пропала, приложение сообщает, что отзыв не подтверждён. Уже запущенная команда
может завершиться. Для отзыва контроллера выполните:

```sh
python3 -m remote222.client --session-file /workspace/.remote222-controller/session.json logout
```

## Данные и обслуживание

База очереди содержит команды, вывод и снимки экрана. `auth.sqlite3` содержит
хеш пароля и данные авторизации. Сохраняйте постоянный диск при обновлении,
ограничивайте доступ к резервным копиям. Файлы сеансов на клиентах дают доступ
к серверу и не должны попадать в репозиторий или журналы.

Перед обновлением остановите новые команды и дождитесь текущей. При потере
ответа повторяйте прежний идентификатор запроса; новый ID может выполнить
действие ещё раз. При удалении сервиса удалите диск, если история больше не нужна.

## Совместимость с прежними ключами

Сервер без настроенного аккаунта сохраняет поддержку двух раздельных ключей
`REMOTE222_CONTROLLER_TOKEN` и `REMOTE222_WORKER_TOKEN` для клиентов v0.3.
После настройки аккаунта этот способ входа отключён. В текущем EXE поле ключа
очереди заменено полями логина и пароля. Прямой Cloudflare-режим по-прежнему
использует свой ключ `REMOTE222_TOKEN`; инструкции есть в [README](../README.md).

Сборка образа для проверки:

```sh
docker build -t remote222-broker .
```

Она не размещает публичный сервер и не подтверждает доступность VPS или Windows.
