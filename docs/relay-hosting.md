# Посредник для одного компьютера

Windows и контроллер в облачной среде подключаются исходящими HTTPS-запросами к
одному посреднику. Он хранит очередь команд и результаты в SQLite. На Windows
не нужны публичный IP, входящий порт или Cloudflare Tunnel. Компьютер должен
оставаться включённым, а видимое приложение Remote222 — запущенным.

Это обычный сетевой сервис: его адрес должен быть разрешён обеим сторонам.
Хостинг, прокси или сеть всё ещё могут вернуть HTTP 403 или другую ошибку.
Перед отправкой команд нужно проверить доступность сервиса из этой облачной
среды. Размещение и оплата хостинга выполняются владельцем учётной записи;
данный репозиторий сам ничего не развёртывает.

## Размещение Docker-сервиса

Подойдёт хостинг Docker-контейнеров с постоянным диском и управляемым HTTPS,
например Render Web Service. Параметры ниже задаются в
[панели Render](https://dashboard.render.com/) или другого выбранного хостинга.

1. Создайте сервис из репозитория
   `https://github.com/teplydom12-boop/remote222`, ветка `main`, Dockerfile в корне.
   Выберите одну реплику. Перед активацией проверьте стоимость сервиса и диска
   в панели: постоянный диск может требовать платного тарифа.
2. Подключите **постоянный диск** по пути `/var/data/remote222`. Не заменяйте его
   временной файловой системой контейнера: после перезапуска потеряются очередь
   и сведения об уже выполненных командах. Для небольшой личной установки
   можно начать с 1 ГБ и следить за свободным местом.
3. Создайте два разных случайных секрета длиной 43–128 символов из букв латиницы,
   цифр, `_` и `-`, используя менеджер паролей или генератор секретов хостинга.
   Добавьте их через защищённые
   поля переменных окружения:

   | Имя | Кому разрешён доступ |
   | --- | --- |
   | `REMOTE222_CONTROLLER_TOKEN` | Посредник и контроллер в облачной среде |
   | `REMOTE222_WORKER_TOKEN` | Посредник и приложение на вашем Windows |

   Не помещайте значения в GitHub, команды запуска, обычные текстовые файлы или
   сообщения чата. Не используйте один ключ для обеих ролей. При перезапусках
   сохраняйте те же значения. На хостинге нужны оба секрета, даже если broker
   умеет создавать локальные файлы ключей при самостоятельном запуске.
4. Сервис запускает команду из Dockerfile:

   ```text
   python -m remote222.broker --host 0.0.0.0 --port 8770 --state-dir /var/data/remote222
   ```

   В панели выберите внутренний HTTP-порт `8770` (или `PORT=8770`, если хостинг
   использует эту переменную) и путь проверки состояния `/healthz`. Процесс
   слушает фиксированный порт из команды. HTTPS должен завершаться на штатном
   прокси хостинга; клиентам нужен выданный им канонический адрес `https://…`.
   Не отключайте проверку TLS и не отправляйте ключи на адреса с редиректами.
5. Убедитесь, что прокси пропускает тела запросов размером не менее 12 МиБ:
   протокол допускает результат до 8 МиБ и дополнительный JSON-конверт.
   Не уменьшайте ограничения приложения для приёма недоверенных команд и
   не открывайте второй экземпляр broker поверх того же SQLite-файла.
6. Запустите сервис. Откройте `https://<адрес-сервиса>/healthz` без ключа:
   ответ должен быть успешным и не содержать данные компьютера. Затем выполните
   проверку с этим же адресом из облачной среды, прежде чем подключать Windows.

Образ запускает только broker. Каталог данных создаётся с правами `0700`;
постоянный диск должен позволять процессу читать и записывать этот каталог.
Контейнер не требует доступа к Docker socket, файлам хоста или привилегированного
режима. Не публикуйте внутренний порт напрямую в интернет без HTTPS-прокси.

## Подключение Windows и облачной среды

В новом Remote222.exe выберите «Через сервер очереди», заполните поле
«HTTPS-адрес вашего сервера очереди» и вставьте **ключ рабочего компьютера**
в поле «Ключ компьютера (REMOTE222_WORKER_TOKEN на сервере)».
Оставьте приложение открытым. Закрытие приложения прекращает получение команд.
Старый EXE с режимом только Cloudflare Tunnel для этого не подходит.

В настройках облачной среды сохраните URL посредника как обычный параметр
`REMOTE222_URL`, а значение ключа `REMOTE222_CONTROLLER_TOKEN` с хостинга — как
секрет **`REMOTE222_TOKEN`**. Задайте обычный параметр
`REMOTE222_TRANSPORT=relay`. Привяжите
секрет только к точному имени хоста посредника и разрешите этот же домен
обычным способом через сетевые настройки среды. Не задавайте маску `*`.
После сохранения проверьте доставку настроек в работающую среду.

Проверка подключения из Linux:

```sh
python3 -m remote222.client --transport relay info
```

Перед первой командой контроллер должен получить сведения о подключённом
Windows-компьютере и убедиться, что это нужная машина. Результаты команд,
ошибки и снимки экрана возвращаются через тот же посредник. Если ответ потерян,
проверяйте прежний идентификатор запроса: повтор с новым идентификатором может
выполнить действие ещё раз.

## Данные и обслуживание

Очередь содержит команды, их аргументы, вывод и снимки экрана. Доступ к учётной
записи хостинга и постоянному диску даёт доступ к этим данным. Используйте свой
аккаунт и обычную защиту доступа к нему. Не публикуйте содержимое базы или
резервных копий.

Для обновления образа остановите новые команды, дождитесь завершения текущей
и сохраните диск с данными. Секреты меняются согласованно на посреднике и у
соответствующего клиента. При уничтожении сервиса удалите диск, если хранить
историю и результаты больше не нужно.

Сборка контейнера для проверки:

```sh
docker build -t remote222-broker .
```

Это только сборка. Она не создаёт публичный адрес, постоянный диск или аккаунт
хостинга и не запускает платный сервис.
