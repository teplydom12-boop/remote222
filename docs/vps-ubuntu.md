# VPS Ubuntu: установка без домена

Этот вариант рассчитан на **новый Ubuntu 22.04 или 24.04 VPS** с публичным IPv4.
На сервере работает только очередь; команды выполняет ваш Windows-компьютер.
Установщик использует Docker с Python 3.13, nginx и Certbot 5.8. Он получает
публичный HTTPS-сертификат для IP, поэтому отдельный домен не требуется.
Доступ из конкретной облачной среды проверяется после установки: отсутствие
сетевых ошибок, включая HTTP 403, заранее не гарантируется.

## Перед запуском

- Откройте приватную root-консоль VPS в панели REG.RU. Пароль сервера не нужно
  отправлять в чат. Сервер должен быть новым: существующие веб-сервисы и каталоги
  другой установки скрипт не заменяет.
- Разрешите входящие **TCP 80 и 443** в сетевых настройках VPS. Если внутри Ubuntu
  уже действует firewall, эти порты должны быть разрешены и там. Сохраните
  существующий доступ SSH и доступ через консоль. Не сбрасывайте правила firewall.
- Порт **8770 открывать нельзя**: broker слушает только `127.0.0.1`, nginx обращается
  к нему локально. Docker использует сеть хоста без публикации портов.
- Нужен исходящий HTTPS для репозиториев, Docker Hub, Python Package Index и
  центра сертификации, а также доступ к штатным зеркалам пакетов Ubuntu.

Скрипт не редактирует правила firewall и настройки SSH. Установка Docker может
создать его собственные служебные сетевые правила. Скрипт не покупает услуги и
не меняет тариф VPS.

## Запуск

Получите `scripts/install_vps.sh` из опубликованной версии этого репозитория и
просмотрите его перед запуском. Скрипт устанавливает broker из зафиксированного
коммита `6e75e0975ed51cc1621d1a611e4e31de9db5de17` (v0.3.0).

Если файл находится в текущем каталоге root-консоли:

```sh
PUBLIC_IP=95.163.231.24 bash install_vps.sh --preflight-only
PUBLIC_IP=95.163.231.24 bash install_vps.sh
```

Замените IP, если используете другой сервер. Первая команда проверяет только
локальные условия; она ничего не устанавливает и не обращается за сертификатом.
Для уведомлений центра сертификации можно добавить `--email ваш-адрес` ко второй
команде; без него установка тоже поддерживается.

Установка создаёт приватные файлы ключей автоматически и **не печатает значения**.
При сетевой ошибке, закрытом порте 80 или временном отказе центра сертификации
исправьте причину и повторите ту же команду: ключи и база сохраняются. Не удаляйте
каталог данных и не повторяйте выпуск сертификата в цикле при ограничении частоты
запросов. Скрипт не переустанавливает ОС и не мигрирует установку на другой IP.

## Подключение

После сообщения «Готово» откройте `https://95.163.231.24/healthz` на Windows.
Ожидается JSON с `"ok": true` и `"service": "remote222-broker"`. Проверка через
`curl` внутри установщика проверяет TLS на самом VPS; отдельно нужно проверить
доступность адреса из Windows и облачной среды.

В приватной консоли или файловом просмотрщике панели самостоятельно скопируйте
значения следующих файлов. Не присылайте их в чат, журнал установки или снимок
экрана. Команды просмотра с выводом ключей не должен выполнять облачный агент.

| Файл на VPS | Куда вставить значение |
| --- | --- |
| `/var/lib/remote222/worker.token` | Поле «Ключ компьютера» нового Remote222.exe |
| `/var/lib/remote222/controller.token` | Секрет облачной среды `REMOTE222_TOKEN` |

В Remote222.exe выберите «Через сервер очереди» и задайте адрес
`https://95.163.231.24`. Приложение должно оставаться открытым.

В облачной среде задайте `REMOTE222_URL=https://95.163.231.24` и
`REMOTE222_TRANSPORT=relay`. Секрет контроллера привязывается только к точному
адресу сервера; сетевое разрешение добавляется штатным способом через настройки
среды. Не используйте широкие маски и не отключайте TLS-проверку.

Сначала проверяется доступность `/healthz` из облачной среды, затем сведения о ПК:

```sh
python3 -m remote222.client --transport relay info
```

## Обслуживание

Сертификат IP имеет короткий срок действия. Установщик включает таймер проверки
продления **дважды в сутки** со случайной задержкой до часа. После успешного
продления nginx проверяет конфигурацию и перечитывает сертификат. Порт 80 должен
оставаться доступным для следующих проверок центра сертификации.

```sh
systemctl list-timers remote222-cert-renew.timer
systemctl status remote222-cert-renew.timer
journalctl -u remote222-cert-renew.service --no-pager -n 40
docker logs --tail 40 remote222-broker
```

Ошибка обновления сертификата требует исправления до его истечения. Проверяйте
таймер и журнал после установки и перезагрузок. Дополнительный платный сертификат
или панель управления не требуются.

Постоянные данные и ключи находятся в `/var/lib/remote222`, служебный маркер
установки — в `/etc/remote222-vps`, исходники — в `/opt/remote222/src`.
Контейнер имеет доступ на запись только к каталогу данных; корневая файловая
система доступна только для чтения, capabilities отключены. Корневой пользователь
VPS по-прежнему имеет доступ к данным и ключам.

База содержит команды и результаты, включая снимки экрана. Сохраняйте её вместе
с ключами при резервном копировании в защищённое место. При неясном результате
команды используйте прежний идентификатор запроса, чтобы не повторить действие.
