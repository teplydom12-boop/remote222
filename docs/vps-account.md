# Обновление VPS: вход по логину и паролю

Этот сценарий обновляет сервер, установленный через `scripts/install_vps.sh`.
Новый Remote222.exe использует адрес сервера, логин и пароль. Разрешение для чата
выдаётся через страницу подтверждения в вашем браузере; переносить ключи в
настройки облачной среды не требуется.

## Что нужно до обновления

- Существующая рабочая установка на Ubuntu 22.04/24.04 с каталогом
  `/var/lib/remote222` и приватной root-консолью REG.RU.
- Для VPS `95.163.231.24` подготовлено имя **`95-163-231-24.sslip.io`**. Сервис
  sslip.io возвращает IP, записанный в имени; запросы идут непосредственно на VPS.
  Покупать домен или создавать ещё один аккаунт для этого варианта не нужно.
  Скрипт повторно проверяет DNS до изменений. Если используете свой домен,
  он должен указывать только на публичный IPv4 этой установки.
- Входящие TCP 80/443 должны оставаться разрешёнными. Порт 8770 остаётся локальным.
- Закройте Remote222.exe и дождитесь завершения уже запущенных действий.

Доменное имя устраняет обнаруженную проблему проверки сертификата IP в текущем
облачном прокси. Оно указывает непосредственно на ваш VPS. Сетевая доступность
из каждой среды всё равно проверяется отдельно; обход сетевых правил не нужен.

## Запуск в приватной консоли VPS

Закройте Remote222.exe. В root-консоли REG.RU скачайте обновление выпуска 0.4.0
и запустите его:

```sh
curl -fL https://raw.githubusercontent.com/teplydom12-boop/remote222/v0.4.0/scripts/upgrade_vps_account.sh -o /root/remote222-upgrade.sh && bash /root/remote222-upgrade.sh
```

Для отдельной предварительной проверки доступно
`bash /root/remote222-upgrade.sh --preflight-only`: она не меняет VPS и не
запрашивает сертификат. Обычный запуск получает сертификат для имени, собирает
закреплённую версию и предлагает создать логин и пароль. **Пароль вводится непосредственно в приватной
консоли и не отображается. Не присылайте его в чат.** Не передавайте пароль через
аргументы команд, переменные окружения или снимки экрана.

Свой домен можно передать как `PUBLIC_HOST=ваше.имя bash /root/remote222-upgrade.sh`.
Скрипт не перебирает домены при отказе центра сертификации. При HTTP 429 остановитесь
и дождитесь указанного срока повторной попытки; старый сервер до переключения
остаётся доступен. До фактической установки сертификата новое имя ещё не готово
для входа по HTTPS.

Старый HTTPS по IP остаётся действующим до успешного получения нового сертификата.
При переключении будет короткий перерыв. База SQLite, история запросов и прежние
файлы ключей сохраняются. Новая версия использует вход в аккаунт и подтверждённые
сеансы вместо ручного обмена ключами. Она запускается в режиме только аккаунта:
при потере базы аккаунта прежние ключи автоматически не включаются.

## Подключение Windows и чата

1. Установите новый [Remote222.exe v0.4.0](https://github.com/teplydom12-boop/remote222/releases/download/v0.4.0/Remote222.exe).
2. Введите `https://95-163-231-24.sslip.io` (либо выбранное своё имя), логин и пароль. Оставьте приложение
   открытым на Windows. Администраторские права Windows не требуются.
3. Сообщите в чат **только HTTPS-адрес**. Ассистент создаст запрос подключения и
   даст ссылку для подтверждения.
4. Откройте ссылку в своём браузере, проверьте адрес сервера, войдите в аккаунт и
   подтвердите этот запрос. Пароль остаётся между вашим браузером и вашим VPS.
5. После подтверждения ассистент проверит сведения о подключённом Windows-ПК.
   Далее команды и обратная связь идут через существующую очередь.

Одно подтверждение привязывает сеанс управления. Не подтверждайте неожиданные
запросы. При завершении или истечении сеанса может понадобиться повторное
подтверждение. Старые ручные настройки `REMOTE222_TOKEN` для этого входа не нужны.

## Ошибки и возврат прежней версии

Если ошибка произошла до переключения, исправьте причину и повторите ту же
команду. После начала настройки аккаунта скрипт **не запускает старую версию
автоматически**: она снова включила бы прежние ключи. Повторный запуск продолжает
обновление; уже настроенный пароль сохраняется.

Для осознанного возврата прежней версии выполните:

```sh
bash /root/remote222-upgrade.sh --rollback
```

Возврат использует **текущую базу** и не заменяет её старой копией: выполненные
задания и их идентификаторы не теряются. Он **снова включает прежнюю авторизацию
по ключам**, поскольку v0.3.0 не поддерживает аккаунт. Старый IP-сертификат должен оставаться
действительным; после его истечения потребуется продление. Не возвращайте базу
из резервной копии поверх новых запросов без отдельной проверки.

Остановленный прежний контейнер сохраняется как `remote222-broker-before-account`.
Закрытая резервная копия базы и прежние конфигурации находятся в
`/etc/remote222-vps/account-upgrade`. Не публикуйте этот каталог.
Хеш пароля и сведения о сеансах новой версии хранятся в отдельном файле
`/var/lib/remote222/auth.sqlite3`; исходный пароль в нём не сохраняется.
Включите этот файл в приватные резервные копии вместе с базой очереди.

Проверка продления нового сертификата:

```sh
systemctl list-timers remote222-cert-renew.timer
journalctl -u remote222-cert-renew.service --no-pager -n 40
```

Таймер продолжает проверять сертификат дважды в сутки. Установщик не меняет SSH,
правила firewall, тариф VPS и не удаляет прежние данные.
