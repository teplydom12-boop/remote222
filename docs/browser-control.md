# Подготовленное управление Chrome через код

Облачный клиент `remote222.browser` выполняет команды в установленном Google
Chrome на Windows через Chrome DevTools Protocol (CDP). Состояние страницы
возвращается как JSON: адрес, заголовок, текст и элементы DOM. Скриншоты и
координаты мыши для этого не используются.

Нужны работающий Remote222.exe 0.4.0, подтверждённый сеанс контроллера, Python
3.12+ в облачной среде, Google Chrome и встроенный Windows PowerShell 5.1 на ПК.
Новые Python-пакеты, драйвер браузера, отдельный сервер и обновление EXE не нужны.
Команды запускаются из checkout репозитория.

## Однократная подготовка

```sh
python3 -m remote222.browser \
  --session-file /workspace/.remote222-controller/session.json \
  --state-file /workspace/.remote222-controller/browser-state.json \
  install --expected-hostname MY-PC
```

Подставьте имя компьютера, подтверждённое владельцем. Установка сохраняет
проверенный PowerShell-помощник в `%LOCALAPPDATA%\Remote222\tools`, а в облаке —
настройки его использования. В файл настроек браузера пароль и сеанс входа
не копируются. Помощник проверяется по SHA-256 перед выполнением; каждая команда
проверяет имя Windows-компьютера.

Можно явно указать `--chrome-path` и `--profile-directory`, чтобы использовать
ранее подготовленный профиль. Обычный пользовательский профиль Chrome для CDP
не подходит: современные версии Chrome требуют отдельный `user-data-dir`.
Профиль автоматизации сохраняется между командами; входы в сайты внутри него
также сохраняются. Окно Chrome остаётся видимым на ПК.

## Готовые команды

У всех примеров один префикс:

```sh
python3 -m remote222.browser --session-file /workspace/.remote222-controller/session.json --state-file /workspace/.remote222-controller/browser-state.json COMMAND
```

| COMMAND | Действие |
| --- | --- |
| `system` | Данные ПК, среды выполнения и открытых окон из системных API |
| `status` | Состояние подготовленного Chrome |
| `start` | Подключиться к существующему окну или запустить подготовленный профиль |
| `tabs` | Адреса, заголовки и ID вкладок |
| `open https://www.1688.com/` | Открыть страницу, дождаться готовности и вернуть её состояние |
| `inspect` | Получить текущее состояние страницы и сведения из DOM |
| `eval --expression 'document.title'` | Выполнить JavaScript в выбранной вкладке и получить результат |
| `save --output /workspace/1688.html` | Сохранить текущий HTML на ПК и получить проверенную копию в облаке |
| `save --url https://www.1688.com/ --output /workspace/1688.html` | Открыть страницу и сохранить HTML одной командой |

Для длинного JavaScript используйте `eval --expression-file script.js`.
По умолчанию используется последняя выбранная вкладка. Выбирайте другую по
`--target-id`, если их несколько. Код и селекторы готовьте
по текущему DOM. Не предполагайте наличие элемента по старому результату.

`save` передаёт HTML в сжатом виде, проверяет размер и SHA-256 после получения.
Это DOM после загрузки, включая выполненный JavaScript. Внешние файлы ресурсов,
отдельные iframe и shadow DOM не включаются в `outerHTML`. Вход или проверка
доступа на сайте могут потребовать действий владельца.

## Почему повторные действия быстрее

Помощник уже находится на Windows: облачный клиент отправляет короткую команду
с параметрами. Chrome, профиль и выбранная вкладка используются повторно.
Открытие страницы, ограниченное ожидание готовности и получение состояния
выполняются внутри одного задания очереди. Сохранение HTML добавляет передачу
сжатого файла. Время загрузки сайта и доступность ПК всё равно влияют на результат.

В проверке через реальный Windows 11 и VPS получение состояния, списка вкладок
и результата JavaScript заняло 3–4,2 секунды. Экспорт уже открытой страницы 1688
размером 2,34 МБ с передачей файла занял 9,5 секунды; повторное открытие сайта,
ожидание до 10 секунд и экспорт — 19,8 секунды. Это отдельные замеры, а не
гарантированное время выполнения.

Ожидание по умолчанию ограничено 1500 мс; `--wait-ms` позволяет задать до
15000 мс. Проверяйте возвращённое `ready_state`: после истечения ожидания страница
может быть ещё `interactive`. HTML в таком случае отражает состояние на момент
экспорта. Неподтверждённый переход не выдаётся за код новой страницы.
Текущий предел экспорта — 16 МиБ HTML и 1 МиБ сжатого файла для передачи.

Не выполняйте отдельные `info`, `status` и снимок экрана перед каждой браузерной
командой: подготовленный помощник проверяет компьютер в самом задании. В начале
сеанса управления и после переподключения проверьте свежий ответ Windows.

Перед отправкой задания клиент сообщает его ID. Если ответ потерялся,
повторите **ту же команду с теми же аргументами** и `--request-id ID` перед
подкомандой. Не создавайте новый ID для действия с неизвестным результатом.
Повтор уже завершённого ID возвращает прежний результат; для новой проверки
состояния нужен новый запрос.

Отладочное соединение остаётся на loopback Windows и проходит через существующий
агент. Входящие порты ПК, отключение TLS, изменение политики PowerShell и
автозапуск дополнительного сервиса не требуются. Основной профиль Chrome не
перезапускается. Если окно автоматизации закрыто, используйте `start` или `open`.
