# Remote222 — управление Windows 11 из чата

[Скачать Remote222.exe](https://github.com/teplydom12-boop/remote222/releases/latest/download/Remote222.exe)
· [Все выпуски](https://github.com/teplydom12-boop/remote222/releases)
· [Архив исходников](https://github.com/teplydom12-boop/remote222/raw/refs/heads/main/dist/remote222-windows.zip)

Агент выполняет команды в вашей интерактивной сессии Windows. Клиент в облачной
Linux-среде отправляет их через HTTPS: через ваш сервер очереди или напрямую
через туннель. Доступны запуск программ, PowerShell,
файлы, снимки экрана, ввод текста, сочетания клавиш, мышь и прокрутка.
Полный доступ разрешается при явном запуске агента, без подтверждения каждой команды.

```text
Ваше сообщение → облачный клиент → ваш HTTPS-сервер очереди
                                           ↑       ↓
                                    результаты   задания
                                           ↑       ↓
                                  Remote222.exe на Windows
                                           ↓
                                  программы и рабочий стол
```

## Запуск одним EXE

### Через сервер очереди — режим по умолчанию

Windows сама забирает задания и загружает ответы. Входящие подключения к ПК,
SSH, открытые порты роутера и Cloudflare Tunnel в этом режиме не нужны.
Ассистент получает вывод команд, ошибки, файлы и запрошенные снимки экрана.

**Сервер не включён в скачивание EXE и автоматически не создаётся.** Нужен
ваш аккаунт хостинга с HTTPS и постоянным диском. Для VPS с Ubuntu 22.04/24.04
есть [установщик с HTTPS на публичный IP, без домена](docs/vps-ubuntu.md).
Для управляемого Docker-хостинга — [инструкция размещения](docs/relay-hosting.md).
Хостинг может быть платным; сначала проверьте условия и стоимость выбранного сервиса.
Обе стороны должны иметь явно разрешённый доступ к адресу сервера. Смена схемы
не гарантирует отсутствие HTTP 403 или других сетевых отказов.

1. Разместите сервер: установщик VPS сам создаёт два отдельных ключа в закрытом
   каталоге данных. На управляемом хостинге сохраните два разных секрета в его защищённых настройках:
   `REMOTE222_CONTROLLER_TOKEN` — для облачного клиента,
   `REMOTE222_WORKER_TOKEN` — для Windows. Не публикуйте их в репозитории или чате.
2. Скачайте **Remote222.exe**, выберите **Через сервер очереди**, укажите HTTPS-адрес
   сервера и ключ компьютера `REMOTE222_WORKER_TOKEN`. Поле ключа скрыто; значение
   хранится только в памяти окна и после закрытия нужно ввести снова.
3. Нажмите **Включить управление**. Готовность означает соединение Windows с
   сервером; доступ из облачной среды проверяется отдельно.
4. Отправьте в чат только HTTPS-адрес сервера. В настройках облачной среды
   разрешите его точный домен, установите `REMOTE222_URL` и `REMOTE222_TRANSPORT=relay`,
   а значение **ключа управления** поместите в секрет `REMOTE222_TOKEN`, ограниченный
   тем же доменом. Ключ компьютера не заменяет ключ управления.
5. Ассистент выполняет `python3 -m remote222.client --transport relay info`, проверяет
   ответ Windows и только затем выполняет ваши команды.

Каждое задание получает устойчивый ID, срок начала исполнения и адресуется
текущему включению агента. Старые задания не запускаются после перезапуска EXE.
Результат хранится отдельно от задания; повторная доставка одного ID использует
локальную историю выполнения. Просрочка, потеря связи или `outcome_unknown` не
означают, что действие точно не выполнилось. Сначала проверяйте состояние ПК.

Кнопка **Отключить** прекращает получение новых заданий. Уже начатая команда
может завершаться; закрытие окна ждёт завершения рабочего потока. Сам сервер
не даёт ассистенту фонового доступа вне активной работы над вашим запросом.

### Прямой туннель Cloudflare — прежний режим

1. Скачайте **Remote222.exe** из раздела Releases и запустите двойным щелчком.
   Нужна Windows 11 x64. Python и компонент туннеля уже находятся внутри файла;
   отдельно устанавливать программы или выполнять PowerShell-команды не нужно.
2. Выберите **Прямой туннель Cloudflare** и нажмите **Включить управление**. Приложение проверит локальный агент и
   HTTPS-соединение. После появления статуса **Управление включено** нажмите
   **Скопировать адрес** и отправьте его в чат.
3. Нажмите **Скопировать ключ**. Вставьте ключ только в секрет `REMOTE222_TOKEN`
   в настройках облачной среды; разрешённый домен — точное имя хоста из адреса.
   Переменная `REMOTE222_URL` должна содержать полный HTTPS-адрес. В чат ключ
   отправлять не нужно. Эти настройки выполняются один раз для текущего адреса.
4. Сохраните настройки и напишите в чат, например: «Открой Блокнот».

Кнопка **Отключить** или закрытие окна прекращают приём команд и закрывают туннель.
Введённые в облачную среду ключи не нужно заново копировать после каждого запуска;
адрес Quick Tunnel при перезапуске меняется, поэтому нужно обновить URL и домен
секрета. Доступно копирование ключа без его показа на экране. Приложение не
устанавливает автозапуск и не запрашивает права администратора.

EXE распаковывает встроенные компоненты во временную папку при запуске, а настройки
и журнал сохраняет в `%LOCALAPPDATA%\Remote222`. Компонент Cloudflare закреплён
на версии 2026.10.1 и проверяется по официальному SHA-256 при сборке и запуске.
Приложение не подписано сертификатом издателя; Windows может показать предупреждение
о неизвестном издателе. Контрольная сумма EXE прилагается к выпуску.

## Запуск из исходников (для разработки)

Нужны Windows 11, обычная учётная запись с открытым рабочим столом и интернет.
Python 3.12+ и cloudflared устанавливаются из официальных пакетов через winget.
Дополнительных Python-пакетов нет. Установка cloudflared может вызвать окно UAC;
сам агент запускайте **без прав администратора**.

1. Распакуйте архив проекта в постоянную папку, например
   `C:\Users\ВашеИмя\Remote222`. Не запускайте файлы прямо из ZIP.
2. Откройте в этой папке PowerShell. Для загруженного из интернета архива,
   после просмотра скриптов разблокируйте только скрипты этого проекта:

   ```powershell
   Get-ChildItem .\scripts\*.ps1 | Unblock-File
   ```

3. Установите необходимые программы:

   ```powershell
   powershell -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\Install-Remote222.ps1
   ```

4. Откройте новый терминал PowerShell в той же папке и запустите:

   ```powershell
   powershell -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\Start-Remote222.ps1
   ```

   Политика выполнения задаётся только для этого процесса PowerShell. Глобальные
   настройки Windows не меняются. Также можно использовать `START.cmd`.
   Появится видимое окно агента и адрес вида `https://….trycloudflare.com`.
   Оставьте окна открытыми. Автозапуск, служба Windows и задания планировщика не создаются.

5. Отправьте **только HTTPS-адрес** в чат. По нему ассистент сможет добавить точный
   домен в сетевые настройки и объявить секрет `REMOTE222_TOKEN`.
   Ключ не отправляйте в чат и не включайте в адрес.

6. Скопируйте ключ на компьютере:

   ```powershell
   powershell -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\Copy-AccessKey.ps1
   ```

   В настройках облачной среды вставьте его в секрет `REMOTE222_TOKEN`, разрешив
   отправку **только на точное имя хоста из адреса агента**, без `https://` и пути.
   В переменную `REMOTE222_URL` укажите полный HTTPS-адрес. Сохраните настройки.
   После вставки очистите буфер обмена: `Set-Clipboard -Value ""`.

7. Сообщите, что настройки сохранены. Ассистент проверит `info`, затем по вашей
   команде сможет открыть Блокнот. До запуска агента и подключения секрета чат
   не имеет доступа к вашему компьютеру.

Нажатие Enter в окне запуска закрывает туннель и агент. Закрытие окна самого
агента также прекращает приём команд. Уже открытые программы останутся открыты;
остановка агента не отменяет выполненные операции.

## Использование из Linux

Команды выполняются из корня проекта. Секрет поступает из настроек среды;
не записывайте его в команды, `.env` в репозитории или историю терминала.
Для сервера очереди добавьте `--transport relay` перед названием действия
или задайте не секретную переменную `REMOTE222_TRANSPORT=relay`.
Все команды ниже поддерживаются обоими способами подключения.

```bash
python3 -m remote222.client info
python3 -m remote222.client open notepad.exe
python3 -m remote222.client text 'Привет из облачной среды!'
python3 -m remote222.client keys ctrl+s
python3 -m remote222.client shell 'Get-Process | Select-Object -First 10'
python3 -m remote222.client list 'C:\Users'
python3 -m remote222.client read 'C:\Users\имя\Desktop\note.txt' --output /tmp/note.txt
python3 -m remote222.client write 'C:\Users\имя\Desktop\note.txt' --input /tmp/note.txt --overwrite
python3 -m remote222.client screenshot --output /tmp/screen.jpg
python3 -m remote222.client mouse 400 300 --button left
```

У текстового ввода нет выбора окна: он попадает в текущее активное окно.
Сначала проверяйте снимок экрана. Координаты мыши — физические координаты
полного рабочего стола. Снимок может быть уменьшен; для пересчёта используются
`left`, `top`, `desktop_width`, `desktop_height`, `image_width`, `image_height`
из ответа: `x = left + image_x * desktop_width / image_width`, аналогично для `y`.

Для запуска программы с аргументами: `open программа.exe аргумент1 аргумент2`.
Без аргументов Windows использует обычное открытие программы/файла/URL через
ассоциации оболочки. Успешный ответ `open` означает принятие запроса запуска;
появление нужного окна проверяется отдельно снимком экрана или списком процессов.

## Соединение и повторные команды

Каждая операция получает идентификатор, который клиент печатает **до отправки**.
Если связь оборвалась, повторяйте точно ту же команду с тем же идентификатором:

```bash
python3 -m remote222.client --request-id ИДЕНТИФИКАТОР open notepad.exe
```

Агент вернёт сохранённый результат, не открывая второй Блокнот. Для завершённых
запросов хранятся последние 100 ответов; идентификаторы сохраняются и после
удаления старых ответов. Если агент завершился во время выполнения, ответ будет
`outcome_unknown`: нужно проверить состояние ПК, прежде чем отправлять новую
операцию. `agent_busy` означает, что выполняется другая команда; повторите позже
с тем же идентификатором. Автоматических повторов управляющих команд нет.

По умолчанию PowerShell-команда ограничена 30 секундами (`--timeout` до 300).
При тайм-ауте завершается дерево её процесса. HTTPS-прокси может оборвать долгий
запрос раньше; это не доказывает, что команда не выполнилась.
Вывод ограничен последними 128 КиБ каждого потока. Передача одного файла — до 1 МиБ.
Запись существующего файла требует `--overwrite`. Для объёмных данных используйте
команды на самом компьютере или отдельный согласованный способ передачи.

## Доступ и ограничения

- Сервер очереди использует отдельные ключи для управления и компьютера. Он
  хранит команды и результаты, поэтому размещайте его только в доверенном
  аккаунте, на постоянном диске с ограниченным доступом. Последние 100
  результатов сохраняются для повторного чтения, идентификаторы — для защиты
  от повторного исполнения. Снимки экрана создаются по запросу, видеопотока нет.
- Разрешение адреса в конфигурации и работа локальных тестов не доказывают,
  что соединение с вашим компьютером доступно. Проверка `info` должна пройти
  через реально выбранный сервер из той же облачной среды.
- Агент слушает только `127.0.0.1`; проброс портов роутера не нужен. В прямом
  режиме доступ извне идёт через Cloudflare; в режиме очереди EXE сам опрашивает сервер.
- Все API-запросы требуют случайный ключ доступа (256 бит). Клиент проверяет TLS,
  запрещает HTTP вне loopback и не передаёт ключ при перенаправлениях.
- Ключ и локальная история лежат в `%LOCALAPPDATA%\Remote222`. Скрипт ограничивает
  права папки текущим пользователем и SYSTEM. `audit.log` содержит идентификаторы,
  типы действий и статусы, без ключей, команд и содержимого файлов. База
  `commands.sqlite3` содержит результаты, включая вывод команд и данные файлов.
- Для отзыва ключа остановите агент и туннель, удалите `access.token`, затем
  запустите агент и обновите секрет в облачной среде. Не удаляйте базу запросов,
  если нужна защита от повторного выполнения старых команд.
- Quick Tunnel получает новый адрес при перезапуске. Обновите `REMOTE222_URL`
  и разрешённый домен секрета. Для постоянного использования настройте именованный
  Cloudflare Tunnel со своим доменом на тот же локальный порт. Он не создаётся
  автоматически и требует аккаунта/домена; см. документацию Cloudflare.
- Сон, выключение и закрытый агент делают ПК недоступным. Заблокированный рабочий
  стол, экран входа, UAC и окна с более высокими правами не управляются обычным
  агентом. Защищённые сочетания вроде Ctrl+Alt+Del не поддерживаются.
- Туннель не даёт чату фонового доступа сам по себе: ассистент отправляет команды
  только при работе над вашим запросом и наличии инструментов/секрета в среде.

## Проверка и сборка EXE

```bash
python3 -m unittest discover -s tests -v
```

Тесты поднимают настоящий HTTP-сервер на loopback, проверяют авторизацию,
отказы при перенаправлении, запуск дочернего процесса, PowerShell/Bash, тайм-ауты,
чтение/запись файлов, повторные запросы и сохранение состояния. На Linux
проверяется явный отказ Windows-операций, а не их успешное выполнение.

Для ручной проверки рабочего стола Windows (откроется Блокнот и будет введён текст):

```powershell
powershell -NoProfile -ExecutionPolicy RemoteSigned -File .\scripts\smoke-windows.ps1
```

GitHub Actions запускает этот набор на Linux и Windows. Затем на Windows создаётся
EXE и запускается его самопроверка: встроенный cloudflared, загрузка интерфейса Tk,
Windows API, настоящий HTTP-агент, PowerShell и передача файлов. Результат
`windows-selftest.json` и `Remote222.exe.sha256` прикладываются к выпуску.
Проверка на сборочном сервере не доказывает работу внешнего туннеля и ввода
на вашем рабочем столе: это проверяется после подключения вашего компьютера.

Собрать EXE самостоятельно в Windows:

```powershell
python -m pip install -r requirements-build.txt
python scripts/build_windows.py
.\dist\Remote222.exe
```

Сборщик загружает официальный cloudflared и проверяет закреплённый SHA-256.
PyInstaller включает Python, Tk, cloudflared и агент в один `dist/Remote222.exe`.
Сборка для Windows из Linux через PyInstaller не поддерживается; используйте
workflow **Build Windows EXE**. Push тега `v*` после успешных проверок автоматически
публикует GitHub Release. Обычный push в `main` создаёт загружаемый артефакт Actions.

Сторонние компоненты: Python — PSF License, cloudflared — Apache-2.0, PyInstaller —
GPL с исключением для распространяемых приложений. Лицензии Python и cloudflared
включены в EXE; исходники компонентов доступны в их официальных репозиториях.

Собрать архив для переноса на ПК: `python3 scripts/build_bundle.py`.
